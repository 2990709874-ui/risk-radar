# 可配置投资监控与风险雷达

投资者用一句自然语言描述关注点，系统把它转成可检查、可修改的规则，并作为长期运行的监控任务持续评估。每次评估都会解释"为什么触发 / 为什么没触发"，数据异常时降级并说明原因，而不是静默假装正常。

## 在线体验

公网可访问地址：https://risk-radar-production-e5c8.up.railway.app/ （部署于 Railway，需在服务环境变量中配置 `FUYAO_API_KEY`）。

## 目标用户

- 有明确关注点、希望"设好就长期盯"的个人投资者或研究员；
- 需要把零散关注点沉淀为可复用、可审计规则的小型研究团队。

## 核心设计

- **自然语言 → 可检查规则**：一句话输入，经 LLM（或内置解析器兜底）转成结构化 JSON 规则，用户可查看、修改、保存版本。
- **统一任务模型**：价格、事件、日历、热度四类条件统一成同一套结构，支持 AND / OR 组合、冷却、去重窗口。
- **状态机**：`running / paused / cooldown / failed`，失败后按指数退避自动重试并恢复。
- **去重与冷却**：同一触发理由在去重窗口内只记录一次；触发后进入冷却，避免刷屏。
- **版本变化**：规则每次修改都保留历史版本与修改原因，可追溯"为什么这次没响"。
- **降级与解释**：数据缺失、过期、冲突或接口失败时，不生成"正常"结论，而是产出带原因的降级说明。

## AI 的角色

1. 把自然语言关注点解析为结构化规则（主要链路）。
2. 生成触发 / 未触发 / 降级场景下的人类可读解释。
3. 不用于直接预测涨跌或给买卖建议。

## 数据使用

- 配置 `FUYAO_API_KEY`（同花顺金融数据 API）后，行情快照、热股榜、交易日历走真实接口 `https://fuyao.aicubes.cn`，鉴权请求头 `X-api-key`。
- 未配置 key 或切换为「演示」模式时，回退到内置 mock 行情（贵州茅台、平安银行、宁德时代），保证开箱可运行、可演示。
- 公告事件条件当前使用构造的演示数据，解释中会明确标注「演示数据」，不冒充真实公告。
- 仅使用公开行情/榜单/日历字段，不采集用户持仓与隐私。

## 启动方式

```bash
node server.js
```

打开 http://localhost:3000 。可选复制 `.env.example` 为 `.env` 并在启动前加载以配置 LLM 接口。

## 部署

仓库内已提供 `Dockerfile` 与 `render.yaml`，可直接部署到 Render：

1. 用 GitHub 账号登录 [Render](https://render.com)。
2. 顶部选 New → Blueprint，连接本仓库，按 `render.yaml` 一键创建 Web 服务。
3. 在服务的 Environment 里把 `FUYAO_API_KEY` 填为你的同花顺金融数据 API Key。
4. 部署完成后用 Render 分配的公网 URL 访问。

同样可用 Dockerfile 部署到 Railway、Fly.io 等任意支持容器的平台。

当前线上版本部署于 Railway：https://risk-radar-production-e5c8.up.railway.app/

## 已知边界与未做事项

- 存储为进程内存，重启即清空；未接数据库持久化。
- mock 行情为演示数据，未接真实行情推送。
- 公告/事件条件使用演示数据，未接入公开公告关键词检索接口。
- 日历条件当前实现为「是否交易日」判断，未接财报/解禁等个股事件日历。
- 未实现邮件/微信等外部通知渠道。
- LLM 解析依赖外部接口，未配置时退化为少量固定句式解析。
- 未做多用户登录与权限隔离。

## 目录

- `server.js`：HTTP 服务、任务模型、状态机、评估引擎、降级逻辑
- `provider.js`：数据提供层（扶摇真实接口 / mock 降级）
- `public/`：前端页面
- `test/`：`node --test` 测试
- `scripts/smoke.js`：真实数据源冒烟测试
- `docs/AI_USAGE.md`：AI 使用与验证记录
- `docs/TESTING.md`：测试说明
